feat(download): P3 Node sidecar 执行 JS 音源下载（421 测试全绿）

## 核心能力：CLI 自己下载（不走 LX）
LX 的 Open API / Scheme URL 都没有下载端点，唯一可行路径是**执行 JS 音源脚本**。
新增 Node sidecar 复刻 desktop 的执行方式：

    Python → 启动便携 Node → 加载 JS 脚本 → 走 musicUrl 协议取直链
           → Python 用 requests 下载 → 写盘

逆向并实现的关键协议（对照 desktop useInitUserApi.ts:41-66）：
  handler({ source, action:'musicUrl', info:{ type, musicInfo } }, sendResponse)
  → 返回字符串 URL / {url} / {data:{url}}

## 新增命令
- download url   —— 取播放直链（排查用）
- download get   —— 下载单曲（文件名自动取"歌名 - 歌手"）
- download repair —— 批量重下失败曲（默认预演，--apply 才执行）

## 关键实现点（踩坑记录）
- lx.request **必须跟随 3xx**，否则拿不到 kuwo 的 Hm_Iuvt_ cookie
- 返回值形状有 3 种（字符串 / {url} / {data:{url}}），都要兼容
- 按脚本声明的 qualitys 请求，传错会让脚本内部崩
- 脚本往 stdout 打日志 → 只取最后一个 JSON 行

## ★ 资源管理（用户明确要求"不用时要释放"）
Node 为**一次性子进程**：按需启动 → 取到结果立即退出 → 绝不常驻。
- 30s 超时强杀（宿主内还有兜底超时，更快更干净）
- --max-old-space-size=256 限制内存
- try/finally 保证任何路径（成功/失败/超时/Ctrl+C）都终止子进程
  + 删除临时脚本文件
- 不注入 fs / child_process / net，只暴露受控 lx.* 接口

实测：内存峰值 30.7~79.3 MB（约束 ≤300MB）、单次 0.9~1.6s、
跑完无残留进程。
