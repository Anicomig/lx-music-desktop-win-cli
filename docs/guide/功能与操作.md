# 功能与操作

> 面向**使用者**：每个功能能做什么、怎么操作、有什么坑。
> 命令的完整参数见 [`../reference/commands.md`](../reference/commands.md)。

---

## 0. 先搞清三件事

### 0.1 三类"源"

| 叫法 | 是什么 | CLI 里对应 |
|---|---|---|
| **平台标识** | `kg` 酷狗 / `kw` 酷我 / `tx` 企鹅 / `wy` 网易 / `mg` 咪咕 | 所有输出里的 `source` 字段 |
| **平台元数据接口** | CLI 直连各平台**官方**接口去查歌 | `lx search` 等查询命令 |
| **JS 音源脚本** | 第三方 JS 插件，用来换播放地址 | `lx script` 命令组 |

**搜歌靠前者，播放靠后者。** 输出里只有 `kg`/`酷狗音乐`，不会出现 `Flower`/`SixYin`。

### 0.2 什么必须先关掉 LX

| 操作 | 需要关 LX 吗 |
|---|---|
| 搜索、看歌单、看状态、播控制 | ❌ 不需要 |
| **新建/改名/删除歌单、插入歌曲** | ✅ **必须关**（否则被 LX 覆盖） |
| **改配置（开放 API 等）** | ✅ 必须关 |
| **安装/更新/删除音源脚本** | ✅ 必须关 |

CLI 会自己拦：不关就报错并提示。真要用 `--force` 也能写，但**可能丢数据**。

### 0.3 为什么"不装音源脚本就播不了歌"

LX v2.12.5 已把内置播放接口全部停用，音频地址**只能**由 JS 音源脚本给。
所以 `lx search` 能搜到歌，但点播放没声音 —— 用 `lx script list` 看看有没有装、`lx script enable` 切换。

## 1. 查询音乐

### 1.1 搜索

```bash
lx search "yorushika"                     # 默认：聚合全部 5 个平台
lx search "yorushika" --source kg         # 只看酷狗
lx search "yorushika" --sources kg,wy     # 看酷狗+网易
lx search "yorushika" --limit 10 --page 2 # 翻页
```

输出示例：

```
# 搜索 'yorushika' — 聚合全部（15 首）

    1. 老人と海  —  ヨルシカ  · 老人と海  [kg/酷狗音乐]  4:15
       id=116989871_8B4D0B91A150C3BE70058F5D8A668876
    4. あぶく  —  ヨルシカ  · あぶく  [kw/酷我音乐]  3:54
       id=kw_561640590
```

每行包含：**歌名 · 歌手 · 专辑 · [平台/中文名] · 时长 · id**。

> **`id` 很重要**：它是"能落库"的复合 id。酷狗的形态是 `<数字>_<hash>`（**没有 `kg_` 前缀**），
> 其它平台是 `<平台>_<songmid>`。想插入歌单时直接用这个 id。

### 1.2 其它查询

```bash
lx song 116989871 --source kg --hash 8B4D0B91A150C3BE70058F5D8A668876
lx album <album_id> --source kw
lx leaderboard --source kw --board 热歌榜
lx hot --source kg
lx source-list --features        # 看每个平台支持哪些功能
```

> 各平台能力不同（如酷我没 `singer`、酷狗没 `lyric`），用 `--features` 查。

### 1.3 遇到"某个平台没结果"

* 常见原因：**请求太快被平台限流**。等几秒重试即可。
* 聚合模式下单平台失败**不会中断**整体，只是该平台为空 —— 输出里会提示。
* 若长期失败，可用 `--source` 换一个平台。

## 2. 播放控制

### 2.1 基本控制（作用于"当前播放"）

```bash
lx play / lx pause / lx toggle
lx next / lx prev
lx seek 1:30            # 支持 90 / 1:30 / 0:30.5
lx volume 50
lx mute on
lx status               # 看当前状态
lx lyric                # 看当前歌词
```

> ⚠️ **状态变化不是立即的**：发出 `play` 后马上 `status` 可能还是 `paused`，
> 约 1 秒后才变。所以 CLI 只回显"已发送动作"，不谎报"状态已变"。
>
> `status` 的取值是字符串：`playing` / `paused` / `error` / `stoped`（LX 自己的拼写）。

### 2.2 播放**指定**歌曲（Open API 做不到，走 Scheme URL）

```bash
# 方式一：给完整信息
lx play-song --name 老人と海 --singer ヨルシカ --source kg \
             --songmid 116989871 --hash 8B4D0B91A150C3BE70058F5D8A668876

# 方式二：也可以直接把 id 当 songmid（会自动拆出 hash）
lx play-song --name 老人と海 --singer ヨルシカ --source kg \
             --songmid 116989871_8B4D0B91A150C3BE70058F5D8A668876

# 方式三：模糊搜索并播放（不需要 songmid）
lx search-play "又三郎" --singer ヨルシカ
```

> 特点：**无返回值**，且**慢**（`search-play` 实测约 9 秒生效）。
> 切歌过程中 `status` 会短暂变成 `error`，**这不是失败**。

### 2.3 歌单与"不喜欢"

```bash
lx open-list kg 1234567        # 在 LX 里打开歌单
lx play-list kg 1234567 --index 0
lx dislike                     # 不喜欢当前播放曲（Open API 无此能力）
lx collect / lx uncollect      # 收藏/取消收藏**当前播放曲**
```

> ⚠️ Open API 的收藏**只能作用于当前播放曲**，不接受歌曲参数。
> 想收藏任意歌曲，用 `lx playlist add love <song_id> --apply`（写"我喜欢"列表）。

## 3. 歌单

### 3.1 查看

```bash
lx playlist list                # 所有歌单 + 歌曲数
lx playlist list --user-only    # 隐藏内置的"默认列表"/"我喜欢"
lx playlist show <list_id> -n 20
lx playlist find "yorushika"    # 在本地歌单里搜
lx playlist stats               # 统计
```

> 内置歌单 `default`（默认列表）和 `love`（我喜欢）**没有独立元数据行**，
> 只存在于歌曲表里，所以不能改名/删除，但**可以往里加歌**。

### 3.2 ★ 搜索后插入歌单（最常用）

```bash
# 1) 先预演（默认就是预演，不会写库）
lx playlist add <list_id> --from-search "yorushika" --source kg

# 2) 看报告满意后，加 --apply 真正写入
lx playlist add <list_id> --from-search "yorushika" --source kg --apply
```

预演报告长这样：

```
# [预演] 歌单 我的收藏 (userlist_xxx)
  现有 12 首；候选 30 首（search）
  比对口径：id

  将新增      8 首
  已存在跳过  22 首
  疑似重复    1 首

  新增明细：
    + [kg] 老人と海 — ヨルシカ
    ...
这是预演，未写入任何数据。确认后加 --apply 执行。
```

### 3.3 从文件/管道导入

```bash
lx search "yorushika" --json > songs.json
lx playlist add <list_id> --from songs.json --apply

# 或直接管道
lx search "yorushika" --json | lx playlist add <list_id> --from - --apply
```

### 3.4 去重口径 `--dedupe-by`

| 取值 | 判定依据 | 适用 |
|---|---|---|
| `id`（默认） | 复合 id 完全相同 | **保守**，不会误杀 |
| `name+singer` | 歌名+歌手相同 | 跨平台同曲识别 |
| `fuzzy` | 时长 ±5 秒 + 版本词校验 | 最智能，能区分 Live/伴奏 |

> `fuzzy` 会刻意把 `歌名` 与 `歌名 (Live)` 判为**不同曲** —— 这是有意的，防止误合并。

### 3.5 新建 / 改名 / 删除

```bash
lx playlist create "新歌单"        # 需关闭 LX
lx playlist rename <list_id> "新名"
lx playlist delete <list_id>      # 连同歌曲一起删
lx playlist remove <list_id> <song_id>...
```

> 所有写操作**必须关闭 LX**。忘了关会报错提示。

## 4. 音源脚本管理

### 4.1 查看现状

```bash
lx script list          # 已装脚本 + sha256 + 是否被手改 + 当前启用哪个
lx script doctor        # ★ 体检：找出空壳/失效/依赖后端的脚本
lx script active        # 只看当前启用的
lx script repo          # 看仓库里有哪些可装
lx script repo --check  # 顺便查远端版本（联网）
```

### 4.1.1 脚本体检（`script doctor`）—— 排查"搜得到但播不了/下载失败"首选

```bash
lx script doctor            # 人类可读报告
lx script doctor --json     # 结构化输出
```

它会检查并给出建议：

| 检查项 | 说明 |
|---|---|
| **字符数过小** | < 2000 字符 → **疑似空壳**，几乎肯定拿不到播放地址 |
| 头部注释块 | 缺 `@name/@version/@author` → LX 读不到元信息 |
| 转发型脚本 | 识别出依赖的第三方后端域名（**后端挂了脚本就废**） |
| 平台/音质 | 从源码提取支持的平台与音质 |
| 被手改过 | 仅对 **CLI 安装**的脚本有效（GUI 导入的没有哈希可比） |

输出示例：

```
! WARN  聚合API接口 (CF)  v3
        972 字符  类型=proxy
        • 仅 972 字符（正常应 ≥2000）—— 疑似空壳，很可能拿不到播放地址
        • 转发型脚本，依赖第三方后端：api.music.lerd.dpdns.org
        → 换用其它脚本：lx script enable <名字>

✓ OK    [独家音源]  v4   ← 当前启用
        105,158 字符
```

> 💡 **为什么需要它**：`lx script list` 只显示字符数，用户看不出"太小=有问题"。
> 实测某用户启用了 972 字符的空壳，导致 26 首下载失败。

### 4.2 安装

```bash
lx script install flower            # 预演（默认）
lx script install flower --apply    # 真装（从 GitHub 下载，自动回退国内镜像）
lx script install 野花🌷 --apply      # 也可以用中文名
lx script install --file .\my.js --apply     # 本地文件
lx script install --url https://.../latest.js --apply
```

### 4.3 更新

```bash
lx script update --all              # 预演：哪些需要更新
lx script update --all --apply      # 执行
lx script update flower --apply     # 单个
```

> **按内容哈希判断**是否需要更新，不看版本号（版本号不可靠：
> 仓库的 `latest.js` 和你机上已装的可能同版本号但内容不同）。

### 4.4 切换与删除

```bash
lx script enable 野花🌷     # 设为当前音源（改 common.apiSource）
lx script remove 野花🌷 --apply
lx script verify            # 校验文件与脚本头是否合法
```

### 4.5 注意事项

* 更新会**保留原 id** —— 这样你的"当前音源"选择不会跳变。
* 如果你**手动改过**某个脚本，更新会拒绝并提示用 `--force`（防丢改动）。
* 装脚本前**先关 LX**。

## 5. 进程与配置

```bash
lx start --hidden        # 托盘启动
lx start --show          # 显示窗口
lx stop                  # 优雅退出（失败自动强制）
lx is-running

lx config-show           # 看开放 API 与音源配置
lx config-enable         # 启用开放 API（需关 LX，之后重启）
lx config-disable
```

### 5.1 找不到 LX / 换电脑了

```bash
lx where     # 显示 exe 路径、数据目录、以及诊断信息
```

CLI 会按顺序找 LX：

1. 环境变量 `LX_EXE`
2. 常见安装路径（含 C–H 各盘符 `Program Files`）
3. `PATH`
4. **Windows 注册表**（`lxmusic://` 协议关联、卸载信息、App Paths）
5. 有界扫描常见安装根目录

都找不到时，显式指定：

```bash
lx --exe "D:\Program Files (x86)\lx-music-desktop\lx-music-desktop.exe" where
setx LX_EXE "D:\...\lx-music-desktop.exe"      # 永久设置
```

数据目录由 `%APPDATA%\lx-music-desktop\LxDatas` 推导（**换电脑/换账号自动适配**）。
特殊部署可用 `LX_DATA_DIR` 直接指定。

## 7.5 下载记录查询

> ⚠️ **CLI 不能发起下载**（LX 的 Open API 与 Scheme URL 都没有下载端点）。
> 下载只能在 LX 界面里操作。本节命令帮你**看清下载状况**并定位问题。

### 7.5.1 看总览

```bash
lx download stats
```

```
下载记录: 517 条
  完成: 485   失败: 32   未完成: 32
  合计: 16394.5 MB

按状态:   completed 485 / error 32
按质量:   flac 390 / flac24bit 64 / 320k 33 / 128k 30
按来源:   kg 283 / kw 199 / wy 24 / tx 6 / mg 5
```

### 7.5.2 看失败项（含可操作建议）

```bash
lx download failed
```

每条会给出**下一步该怎么做**：

```
✗ Summer Calling — 塞壬唱片-MSR、Jason Walsh
    [wy/128k] 获取音乐链接失败
    建议: 脚本拿不到播放地址 → 检查【当前启用的音源脚本】是否有效
          （lx script doctor），可换脚本后重下

✗ Running In The Dark — MONKEY MAJIK、塞壬唱片-MSR
    [kw/flac] 存在同名文件，跳过下载
    建议: 已存在同名文件被跳过 → 如需覆盖，先在 GUI 删除该文件再下
```

### 7.5.3 校验文件是否真的还在

```bash
lx download verify
```

```
记录 517 条：存在 481，缺失 34，大小异常 2
```

用途：找出**"数据库记录说下载完成，但磁盘上文件没了"**的情况
（手动删过、移动过、清理过）。

> 大小比对默认**容差 10%** —— 因为 LX 下载后会补写 ID3 标签，
> 正常文件也会差 1~2%，用更严的阈值会大量误报。

### 7.5.4 筛选用法

```bash
lx download list --status completed --limit 20
lx download list --source wy
lx download list --quality flac24bit
```

> 全部**只读**，LX 运行时也安全。

## 7.6 下载音乐（CLI 自己下载，不走 LX）

> ⚠️ 与 §7.5 不同：这些命令会**真的下载文件**。
> 实现方式是让 CLI 执行你装的 JS 音源脚本取直链（Node sidecar），
> 再用 HTTP 下载。**不需要 LX 参与**。

### 7.6.1 单曲

```bash
# 1) 先试能否取到直链（不下载）
lx download url 223088839 --source kw

# 2) 下载
lx download get 223088839 --source kw --out D:\Music
```

文件名自动用库里的「歌名 - 歌手」；库里查不到则从直链推断。

**音质**：`--quality flac24bit|flac|320k|128k`（默认 320k）
> 注意：**要按脚本实际支持的音质来要**。传了脚本不支持的音质会失败。
> 用 `lx script doctor` 看每个脚本支持的音质。

**指定脚本**：`--script "Free listen"`（默认用当前启用的）

### 7.6.2 整张歌单批量下载

```bash
# 预演：看会下哪些、多少首
lx download list-all "塞壬唱片" --out D:\Music

# 真正下载
lx download list-all userlist_1791795090583 --out D:\Music --apply
```

| 选项 | 说明 |
|---|---|
| `--limit N` | 只处理前 N 首（先试水） |
| `--apply` | 真正下载（默认只预演） |
| `--overwrite` | 已存在也重新下 |
| `--report r.json` | 结果清单存成 JSON |
| `--json` | 结构化输出 |

歌单可以用 **id** 或**名称**；名称匹配多个时会报错让你改用 id。

### 7.6.3 批量重下失败曲

```bash
lx download failed-all --out D:\Music              # 预演
lx download failed-all --out D:\Music --apply      # 执行
lx download repair --out D:\Music --apply          # 同上（更短的别名）
```

涵盖两类：
1. `status = error` 的失败记录
2. **记录在但文件已丢失**的（`verify` 发现的）

可选 `--source kw` 只处理某平台，`--limit N` 限量。

### 7.6.4 行为说明

| 行为 | 说明 |
|---|---|
| **默认预演** | 不加 `--apply` 只列计划，不启动 Node、不下载、不建目录 |
| 跳过已存在 | 目标目录已有同名且非空文件 → 跳过（`--overwrite` 可关） |
| 失败不中断 | 单曲失败继续下一首，最后汇总（退出码 4） |
| 节奏控制 | 每首间隔 ~0.35s，避免触发平台限流 |
| 清单 | `--report` 可存 JSON（含每首成功/失败原因） |

### 7.6.5 前置条件：Node

CLI 需要 Node 运行时来执行 JS 音源脚本。查找顺序：

1. 环境变量 `LX_NODE`
2. **内置便携版** `<cli-root>/tools/node/node.exe`（发布包自带）
3. 系统 PATH

```bash
lx doctor              # 会报告 Node 宿主是否可用
```

没有 Node 时，`url` / `get` / `list-all` / `failed-all` 会给出明确指引，
**只读命令不受影响**。

### 7.6.6 ⚠️ 安全提示

CLI 会**执行第三方 JS 音源脚本**。Node 的 `vm` **不是安全沙箱**
（脚本理论上可经原型链逃逸）。已做的限制：独立子进程、不注入
`fs`/`child_process`/`net`、30s 超时强杀、内存上限 256MB。

**请只运行你信任的音源脚本。**

> 资源释放：Node 是**一次性子进程** —— 每首取到链接后立即退出，
> 不常驻。批量下载也不会累积进程。

## 8. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `无法连接开放 API` | LX 没启动，或"开放 API 服务"没启用 → `lx config-enable` 后重启 |
| 搜到了但播放没声音 | 没装/没启用 JS 音源脚本 → `lx script list` / `lx script enable` |
| **下载总是失败** | **先跑 `lx script doctor`** —— 多半是启用的脚本是空壳 |
| 写歌单报"LX 正在运行" | 先 `lx stop`，或用 `--force`（有风险） |
| 某个平台搜不到 | 可能被限流，等几秒；或换 `--source` |
| `toggle` 后没变化 | 状态变化有延迟（约 1 秒），用 `lx status` 再确认 |
| `play-song` 后没反应 | Scheme URL 是单向且慢的（秒级），用 `lx status` 确认 |
| 中文乱码（控制台） | 用 `--json`，或 `chcp 65001` |
