# 如何更新

> 三种方式，按推荐程度排序。实测均验证可用。

---

## 方式 A：下载新 zip（**推荐**）

### 步骤

1. 到 [Releases](https://github.com/Anicomig/lx-music-desktop-win-cli/releases)
   下载新版 zip（如 `lx-music-desktop-win-cli-v0.2.1.zip`）
2. **解压到一个新目录**（如 `...\lx-music-desktop-win-cli-v0.2.1\`）
3. 进入该目录，运行：

```cmd
install.bat
```

4. 确认版本：

```cmd
lx --version
lx status-install
```

5. **删除旧目录**（可选但建议，避免两个目录混用）

### 实测验证（v0.2.0 → v0.2.1）

```
步骤1 已装 v0.2.0          → lx, version 0.2.0
步骤2 解压 v0.2.1 跑 install.bat
       离线装依赖          → OK（不联网）
       pip install -e .    → OK（自动覆盖旧版）
       新目录版本          → lx, version 0.2.1
       全局 lx             → lx, version 0.2.1
       status-install      → v0.2.1 mode=editable
                             package_location → 新目录
```

**结论**：全局 `lx` 会自动指向新目录（editable 重定向），无需先卸载。

### ⚠️ 注意

- **旧目录仍是旧代码**：旧目录里的 `run.py` 会加载自己的 `src/`，
  仍显示旧版本。所以更新后**建议删除旧目录**，避免混淆。
- **不要覆盖解压到同一目录**：虽然能工作，但残留的旧文件
  （如已删模块）可能造成奇怪问题。用新目录更干净。

---

## 方式 B：原地更新（同一目录）

如果你一直用同一个目录，想原地更新：

1. 下载新 zip
2. **覆盖解压**到原目录（或删掉 `src/` `scripts/` `skills/` 等再解压）
3. 跑 `install.bat`

因为用的是 **editable 安装**（`pip install -e .`），
代码改了就立即生效，通常连 `install.bat` 都不用重跑：

```cmd
lx --version     :: 直接看是不是新版
```

> 只有 `pyproject.toml` 的依赖或入口点变了，才需要重跑 `install.bat`。

---

## 方式 C：git 拉取（开发者）

如果你是 clone 仓库而不是下载 zip：

```cmd
cd lx-music-desktop-win-cli
git pull
install.bat          :: 依赖有变时重跑
```

---

## 怎么知道该不该更新？

```cmd
lx status-install --json     :: 看 cli_version
```

对比 [Releases 页面](https://github.com/Anicomig/lx-music-desktop-win-cli/releases)
的最新版本号。

> 或者跑 `lx doctor`，若某项异常且已发布新版修复，更新即可解决。

---

## 更新会丢数据吗？

**不会。** 更新只替换 CLI 程序文件，不动：

- LX Music Desktop 本体
- `%APPDATA%\lx-music-desktop\LxDatas\`（歌单、配置、音源脚本）

`install.bat` 与 `lx uninstall` 都严格遵守这条边界。

---

## 回退

想回到旧版：安装旧版 zip 即可（方式 A，指向旧目录）。
旧版 release 一直保留在 Releases 页面。
