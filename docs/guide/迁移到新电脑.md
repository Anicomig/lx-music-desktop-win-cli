# 迁移到新电脑

> **结论先说：把 `lx-cli-v2` 整个文件夹拷过去就能用**，
> 只要新电脑有 **Python ≥3.10** 和两个依赖包。
> 不需要 `pip install` 本项目本身，不需要改任何配置。
>
> **遇到问题**先跑 `lx doctor`（v0.2.0+），它会按依赖顺序逐项检查
> 并对每项失败给出可执行的"下一步"命令。
> 本文档 §8 汇总了**另一台 AI 在新机实测踩到**的常见坑（已修复）。

---

## 1. 三步搞定

### 第 1 步：拷贝文件夹

把整个 `lx-music-desktop-win-cli` 目录拷到新电脑任意位置（**路径含中文/空格也可以**）：

```
D:\tools\lx-music-desktop-win-cli\
E:\我的工具\lx-music-desktop-win-cli\
```

> ⚠️ 拷**整个文件夹**（含 `src/`、`run.py`、`wheels/`），不要只拷 `run.py`。

### 第 2 步：装依赖（★ 一键、离线）

```cmd
install.bat
```

脚本会自动：
1. 找 Python（`py` → `python3` → `python`）
2. **用内置 `wheels/` 离线装依赖** —— 不联网、秒级完成
3. 验证 CLI 能启动
4. 可选：装成全局 `lx` 命令
5. 跑 `lx doctor` 自检

> **为什么推荐它**：联网装依赖是过去最大的坑（网络慢/源不通/临时目录受限）。
> 内置 wheels 后完全绕过这些，详见 §8。

**不想用脚本**，手动等价操作：

```cmd
python -m pip install --no-index --find-links wheels click requests
```

### 第 3 步：验证

```cmd
python run.py doctor      :: 一键自检，失败项会直接告诉你怎么办
python run.py where       :: 看能否找到 LX 与数据目录
python run.py --version   :: 应输出 0.2.x
```

## 2. 怎么调用

```bash
python D:\tools\lx-cli-v2\run.py search "yorushika" --json
python D:\tools\lx-cli-v2\run.py status --json
```

想更短一点，二选一：

**方式 A：`lx.bat`**（Windows，双击或命令行）
```bash
D:\tools\lx-cli-v2\lx.bat search "yorushika"
```

**方式 B：装成 `lx` 命令**（可选，需联网）
```bash
cd D:\tools\lx-cli-v2
python -m pip install -e .
lx --version
```

**方式 C：加个 PATH 别名**（不装包，最轻）
把 `D:\tools\lx-cli-v2` 加进 PATH，然后每次 `python %PATH%\lx-cli-v2\run.py` —— 不如直接写全路径方便。

## 3. 新电脑上数据目录会自动找对吗？

**会。** 三件事都是自动的：

| 项 | 怎么找到的 |
|---|---|
| **LX 数据目录** | 读环境变量 `%APPDATA%`（不硬编码用户名/盘符）→ 换账号/换电脑自动适配 |
| **LX 安装位置** | 候选路径（C–H 各盘符 `Program Files`）→ PATH → **注册表**（`lxmusic://` 协议关联/卸载信息）→ 目录扫描 |
| **便携版布局** | `<exe目录>/portable` 存在时自动走 `portable/userData/LxDatas` |

验证：
```bash
python run.py where --json
```

### 找不到时手动指定

```bash
# 临时（本次）
python run.py --exe "D:\Program Files (x86)\lx-music-desktop\lx-music-desktop.exe" where

# 永久（环境变量）
setx LX_EXE "D:\Program Files (x86)\lx-music-desktop\lx-music-desktop.exe"

# 极端情况：数据目录也不在默认位置
setx LX_DATA_DIR "C:\SomeWhere\LxDatas"
```

## 4. 新电脑上还需要什么？

| 需要 | 说明 |
|---|---|
| **Python ≥3.10** | 实测 3.13（32 位/64 位都行） |
| **`click` + `requests`** | `python -m pip install click requests` |
| **LX Music Desktop** | 要装在新电脑上，且**至少打开过一次**（生成 `config_v2.json`） |
| **LX 开放 API 已启用** | 设置 → 开放 API 服务 → 启用<br>或 `python run.py config-enable` 后重启 LX |
| 音源脚本（可选） | 想播放**在线**歌曲就需要（见下） |

### 关于音源脚本

`user_api.json` 也在 `%APPDATA%\lx-music-desktop\LxDatas\` 里，
**登录同一个 Windows 账号**就自动在；否则用 CLI 重新装：

```bash
python run.py script repo --json          # 看有哪些
python run.py script install flower --apply   # 需先关闭 LX
```

## 5. 想要"数据也跟着走"？

LX 的数据在 `%APPDATA%\lx-music-desktop\LxDatas\`，**不在** CLI 文件夹里。

| 目标 | 做法 |
|---|---|
| 同账号换机器 | 数据自动在（同一 Windows 账号） |
| 换账号/想带着走 | 关闭 LX → 拷贝整个 `LxDatas\`（**含 `.db-wal` / `.db-shm`**）→ 放到新电脑对应位置 |
| 只想备份 | `python run.py backup D:\backups\lx`（含 SHA256 清单） |

> ⚠️ **必须在 LX 关闭时拷**，否则 WAL 未落盘，数据可能不一致。

## 6. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'click'` | 依赖没装 | `python -m pip install click requests` |
| `No such command 'script'` / 命令变少 | 加载到了**别处**的旧 `lx_cli` | 用 `run.py` 调用；或确认 PATH 里没有旧安装 |
| `找不到 lx-music-desktop.exe` | 装在了非常规位置 | `--exe` 或 `setx LX_EXE ...` |
| `无法连接开放 API` | LX 没开，或开放 API 未启用 | 启动 LX；`config-enable` 后重启 |
| 搜到了但播不了 | 新电脑没装音源脚本 | `script install <名字> --apply` |
| `ModuleNotFoundError: lx_cli` | 用了 `python -m lx_cli` 但没装 | 改用 `python run.py` |

## 8. 安装为什么变快了（内置 wheels）

### 8.1 问题：联网装依赖是最大的坑

旧流程要求先 `python -m pip install click requests`。实测这一步的依赖链：

| 包 | 体积 |
|---|---|
| click | 887 KB |
| requests | 450 KB |
| urllib3 | 895 KB |
| certifi | 235 KB |
| idna | 471 KB |
| charset-normalizer | 650 KB |
| **合计** | **约 3.5 MB** |

联网下载 3.5 MB，还要看网络/镜像/代理脸色 —— 国内不设镜像可能几十秒到几分钟，甚至超时。

而且它会**连锁放大**其它问题：

```
TEMP 不可写          → pip 构建阶段失败
   ↓ 为绕开它
加 --no-build-isolation
   ↓ 该模式不自动装构建依赖
setuptools 缺失       → 又要预装 setuptools wheel
   ↓
需要更多网络步骤
```

### 8.2 解决：把依赖 wheel 内置进发布包

`wheels/` 目录预置了全部依赖（**707 KB**，已含传递依赖与 SHA256 清单）：

```cmd
:: install.bat 内部执行的就是这一句
python -m pip install --no-index --find-links wheels click requests
```

**`--no-index` 意味着 pip 完全不访问网络索引。**

| 对比 | 旧流程 | 新流程 |
|---|---|---|
| 网络 | 必须 | **完全不需要** |
| 耗时 | 几十秒 ~ 几分钟 | **秒级** |
| 受代理/镜像影响 | 是 | **否** |
| 受 TEMP 限制 | 是（构建隔离） | **基本不受影响** |
| 需要 setuptools | 是（editable 装） | **否** |

### 8.3 关于 `charset-normalizer`

它的 wheel 是**版本绑定**的（如 `cp313-cp313-win32`），不能跨 Python 版本用。

本项目的处理：**版本能对上就内置（性能更好），对不上就跳过** ——
因为 `requests` 在它缺失时会**自动回退到纯 Python 实现**，功能不受影响。

其余 5 个包都是 `py3-none-any`（跨版本通用）。

### 8.4 旧流程仍可用

不想用内置 wheels 也可以联网装（`install.bat` 会在离线失败时自动回退）：

```cmd
python -m pip install click requests
```

## 9. 其它常见坑（排障指引）

> 另一台 AI 在新机安装 v0.2.0 时的真实排障记录，详见
> `_backup/安装排障清单.md`。要点：

### 9.1 `bindLan=true` 时 host 固定 127.0.0.1（已修）★ 502 的真凶

`0.0.0.0` 是监听通配符，**不能**作为客户端连接目标。
新版 `endpoints_from_config()` 不论 `bindLan` 为何，host 都是 `127.0.0.1`。

**实测证据**（在开启系统代理 `127.0.0.1:7890` 的环境下）：

| host | `proxy_bypass()` | 结果 |
|---|---|---|
| `0.0.0.0` | `False`（**不豁免，会走代理**） | **502** |
| `127.0.0.1` | `True`（requests 自动豁免本机） | **200 OK** |

**为什么会产生 502**：旧代码在 `bindLan=true` 时用 `0.0.0.0` 连接。
`requests` 认为 `0.0.0.0` 不是本地地址，于是**把请求发给了系统代理**；
代理又连不上 `0.0.0.0:23330`（那不是可连接目标）→ 502。

> ⚠️ 注意归因：**502 的根因是 `0.0.0.0`，不是"没绕过代理"** ——
> `127.0.0.1` 即便强制走代理也是 200（requests 对本机地址自动豁免）。

### 9.2 本机端点用独立会话绕过代理（加固）

新版为本机 Open API 使用专属 `_local_session()`（`trust_env=False`）。

严格说，在 `host=127.0.0.1` 的前提下 requests 已自动豁免，
这一步**不是 502 的成因**，但保留作为**防御性加固**：

* 某些企业 PAC / 组策略会把 `127.0.0.1` 也代理走
* 用户自定义 `no_proxy` 为空等边缘情况

**分工约定**：本机端点永远绕过代理，外网搜索始终走代理。
`lx doctor` 会同时验证这两条 —— 两者同时 OK 即证明分工正确。

### 9.3 `pip install -e .` 缺 setuptools

只有加了 `--no-build-isolation` 时才会缺。**默认**（不带这个 flag）
pip 会自动在隔离环境里装 `build-system.requires` 里的 `setuptools>=68`。
> 简单点：直接 `python -m pip install -e .` 即可，**别**手动加 `--no-build-isolation`。
> 用 `install.bat` 则根本不会碰到这个问题。

### 9.4 临时目录不可写

若宿主的 `TEMP`/`TMP` 指向不可写目录，pip 在构建阶段会失败。
**修法（Windows）**：
```cmd
set TEMP=C:\Users\<你>\AppData\Local\Temp
set TMP=%TEMP%
```
**免安装方式（`run.py`）不依赖 pip 临时目录** —— 若只是想用 CLI 功能，
直接用免安装方式更省事。

### 9.5 `lyric-all` 端点名的命令别名

Open API 端点叫 `/lyric-all`，CLI 命令叫 `lyric`（配合 `--all`）。
从 v0.2.0 起增加了 **`lyric-all` 别名**，两种写法都行：

```bash
lx lyric --all              # 推荐
lx lyric-all                # 等价
```

### 9.6 状态/搜索分工的反向校验

`lx doctor` 的第 8、9 步同时成功 ⇒ 证明
"本机端点绕过代理" + "外网搜索走代理"两件事**同时正确**。
任一失败都意味着分工被破坏，请报 issue。
